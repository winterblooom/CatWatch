## Что это такое?

**CatWatch** — это инструмент для автоматического анализа журналов событий Windows. Журналы событий (Event Log) — это файлы, в которые Windows записывает всё, что происходит в системе: входы пользователей, запуски программ, ошибки, изменения настроек и т.д. Эти файлы хранятся в формате `.evtx`.

CatWatch читает эти файлы, проверяет каждое событие по 45 правилам и находит подозрительную активность: попытки подбора пароля, запуск хакерских утилит, создание скрытых учётных записей, заметание следов и другие признаки атаки. Результат анализа — наглядный HTML-отчёт, который можно открыть в любом браузере.

## Возможности

- Парсинг файлов `.evtx` (журналы Security, System, Sysmon, PowerShell)
- 45 правил детекции подозрительной активности (30 для Security/System + 15 для Sysmon)
- 4 паттерна корреляции событий (брутфорс, эскалация привилегий, разведка, заметание следов)
- Генерация HTML-отчёта с визуализацией:
  - круговая диаграмма распределения по категориям угроз
  - фильтрация и поиск по срабатываниям
  - сортировка по любому столбцу
  - сворачиваемые детали для длинных записей
  - автоматическое предварительное заключение с оценкой уровня риска
- Экспорт в CSV для дальнейшего анализа в Excel

## Какие угрозы обнаруживает?

| Категория | Что ищет | Примеры Event ID |
|-----------|----------|-----------------|
| Брутфорс | Массовые неудачные попытки входа | 4625, 4740 |
| Манипуляция учётными записями | Создание, удаление, активация учёток | 4720, 4722, 4724, 4726 |
| Эскалация привилегий | Добавление в группу администраторов | 4732, 4672 |
| Перемещение по сети | Входы через RDP, Pass-the-Hash | 4624, 4648 |
| Подозрительные процессы | Запуск хакерских утилит (mimikatz, psexec) | 4688 |
| Подозрительный PowerShell | Закодированные команды, загрузка в память | 4104 |
| Закрепление в системе | Новые службы, задачи, автозагрузка | 7045, Sysmon 13 |
| Разведка | whoami, net user, systeminfo, netstat | 4688, Sysmon 1 |
| Доступ к учётным данным | Обращение к lsass.exe, дамп паролей | Sysmon 10 |
| Уничтожение следов | Очистка журналов, отключение аудита | 1102, 104, 4719 |

## Требования

- **Python 3.10 или выше** (рекомендуется 3.12)
- **Windows** (для экспорта журналов; анализ работает на любой ОС)
- Около 50 МБ свободного места

Проверить установлен ли Python:
```
python --version
```
Если команда не найдена — скачайте Python с [python.org](https://www.python.org/downloads/). При установке **обязательно поставьте галочку** "Add Python to PATH".

## Установка (пошагово)

### Шаг 1 — Скачать проект

**Вариант А** — через Git (если установлен):
```bash
git clone https://github.com/winterblooom/CatWatch.git
cd CatWatch
```

**Вариант Б** — без Git:
1. На этой странице нажмите зелёную кнопку **Code** → **Download ZIP**
2. Распакуйте скачанный архив в удобную папку (например `C:\CatWatch`)
3. Откройте командную строку и перейдите в эту папку:
```bash
cd C:\CatWatch
```

### Шаг 2 — Создать виртуальное окружение

Виртуальное окружение — это изолированная копия Python для проекта. Нужно, чтобы библиотеки проекта не конфликтовали с другими программами.

```bash
python -m venv .venv
```

### Шаг 3 — Активировать виртуальное окружение

**Windows (PowerShell):**
```powershell
.venv\Scripts\activate
```

Если PowerShell выдаёт ошибку "выполнение сценариев отключено", выполните сначала:
```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

**Windows (Командная строка CMD):**
```cmd
.venv\Scripts\activate
```

После активации в начале строки появится `(.venv)` — это значит окружение активно.

### Шаг 4 — Установить зависимости

```bash
pip install -r requirements.txt
```

Эта команда установит все необходимые библиотеки: `python-evtx`, `lxml`, `jinja2`, `colorama`.

### Готово!

Теперь можно запускать анализ. При каждом новом открытии командной строки нужно заново активировать окружение (Шаг 3).

## Как получить журналы Windows для анализа

CatWatch анализирует файлы в формате `.evtx`. Их можно получить двумя способами:

### Способ 1 — Экспорт через командную строку

Откройте **PowerShell от имени администратора** (правой кнопкой → "Запуск от имени администратора") и выполните:

```powershell
wevtutil epl Security C:\CatWatch\test_logs\Security.evtx
wevtutil epl System C:\CatWatch\test_logs\System.evtx
```

Это скопирует журналы Security и System в папку `test_logs` проекта.

### Способ 2 — Через «Просмотр событий»

1. Нажмите `Win + R`, введите `eventvwr.msc`, нажмите Enter
2. В левой панели раскройте **Журналы Windows**
3. Правой кнопкой по нужному журналу (Security, System) → **Сохранить все события как...**
4. Сохраните файл в папку `test_logs` проекта

## Использование

### Анализ одного файла

```bash
python main.py -i test_logs\Security.evtx
```

После выполнения в папке проекта появится файл `report_ДАТА_ВРЕМЯ.html`.

### Анализ нескольких файлов

```bash
python main.py -i test_logs\Security.evtx test_logs\System.evtx -o my_report.html
```

Флаг `-o` задаёт имя выходного файла.

### Анализ всей папки

```bash
python main.py -i test_logs\ -o report.html
```

CatWatch найдёт все `.evtx` файлы в папке и проанализирует их вместе.

### Дополнительно сохранить CSV

```bash
python main.py -i test_logs\ -o report.html --csv alerts.csv
```

CSV-файл можно открыть в Excel для дальнейшего анализа.

### Тестовый запуск (без реальных журналов)

Если у вас нет `.evtx` файлов, можно запустить тест с синтетическими данными:

```bash
python generate_test_data.py
```

Скрипт сгенерирует сценарий атаки (брутфорс → разведка → создание бэкдора → запуск вредоносов → заметание следов) и создаст отчёт `test_report.html`.

## Как читать отчёт

Откройте сгенерированный `.html` файл в любом браузере (Chrome, Firefox, Edge).

**Верхняя панель** — общая статистика: сколько событий проанализировано, сколько подозрительных найдено, сколько из них критических.

**Распределение по категориям** — круговая диаграмма показывает, какие типы угроз обнаружены и в каком количестве.

**Коррелированные инциденты** — CatWatch не просто ищет отдельные подозрительные события, а группирует их в инциденты. Например, 15 неудачных попыток входа с одного IP → один инцидент "Атака брутфорс".

**Предварительное заключение** — автоматическая оценка уровня риска (критический / высокий / средний / низкий / отсутствует) с конкретными рекомендациями.

**Таблица срабатываний** — все обнаруженные подозрительные события с возможностью:
- Поиска по любому полю (строка поиска)
- Фильтрации по уровню критичности (кнопки Critical / High / Medium / Low)
- Сортировки по любому столбцу (клик по заголовку)
- Просмотра полных деталей (кнопка "Показать полностью")

```
├── reporter.py              — генерация HTML и CSV отчётов

├── logo.svg                 — логотип проекта

├── templates/

└── test_logs/               — папка для .evtx файлов
```

## Как это работает (кратко)

1. **parser.py** читает бинарный `.evtx` файл, извлекает XML каждого события и преобразует в Python-словарь
2. **rules.py** проверяет каждое событие по 45 правилам — совпадает ли Event ID, содержат ли поля подозрительные значения
3. **correlator.py** группирует одиночные срабатывания в инциденты (например, серия неудачных входов → брутфорс)
4. **reporter.py** подставляет результаты в HTML-шаблон и генерирует готовый отчёт

## Частые проблемы

**`python` не найден**
→ Python не установлен или не добавлен в PATH. Переустановите Python с галочкой "Add to PATH".

**PowerShell: "выполнение сценариев отключено"**
→ Выполните: `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

**`ModuleNotFoundError: No module named 'Evtx'`**
→ Виртуальное окружение не активировано. Выполните `.venv\Scripts\activate`

**Отчёт пустой (0 срабатываний)**
→ Файл содержит события, не покрытые текущими правилами. Попробуйте экспортировать журнал Security — в нём больше всего полезных событий.

**Время в отчёте показывает N/A**
→ Устаревшая версия парсера. Обновите проект с GitHub: `git pull`
